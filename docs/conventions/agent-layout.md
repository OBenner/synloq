# Agent workspace layout convention

Status: accepted (operator, 2026-11-15). Owner: dev; amendments via PR with CTO review.
Scope: **operational convention for the operator's machine.** This layout is not part of
the product and is not inherited by external users. It organises the local working
spaces of the role team that develops Synloq itself.

## Root

All role spaces live under one root:

```
<repo>/synloq-agents/
```

On this operator's stand the root sits **inside** the repository checkout and is fully
gitignored (see Mitigations). Placing it next to the checkout instead is equally valid
and recommended for anyone else; the convention is identical either way.

The root is never a git repository itself: no clone, no init, no commits at the root
level. Git worktrees inside role folders reference the main checkout's object store.

## Directory structure

```
synloq-agents/
  README.md                  — local copy of these rules (canonical text is this file)
  _stands/                   — ephemeral acceptance/verification stands, TTL + cleanup
  roles/
    <role-id>/               — one folder per role, created on demand
      AGENTS.md              — generated from the manifest; never hand-edited
      .codex/config.toml     — host channel config for codex-desktop roles (no tokens)
      .mcp.json              — host channel config for claude-desktop roles (no tokens)
      notes/ decisions/ tmp/ — the role's persistent scratch space (local only)
      worktrees/<issue>/     — git worktree per active task; removed after merge
```

## Rules

1. **The manifest is applied from the main checkout only.** `synloq init`, `doctor`,
   `repair`, `serve` run only from the main checkout, never from a worktree: running
   the CLI with `--project-root` inside a worktree mints a _new_ project key (the key
   is derived from the canonical project root path), i.e. a new empty stand.
2. **No tokens under `synloq-agents/`.** Role folders are opened in host GUIs, indexed,
   archived and screenshotted. Tokens and the relay database live only in the Synloq
   home; role folders carry paths, never credentials.
3. **A worktree exists per active task, not per role.** Writing roles (dev2, staff\*)
   get one worktree per issue and remove it after merge. Reviewing roles (arch,
   security, tester) get one read-only checkout of main plus a detached worktree per
   PR on demand. Kimi Work roles never create worktrees — they work in the main
   checkout through the client; their heavy journals stay in `docs/local/<role>/`.
4. **Folder names are stable role IDs without a host suffix** (`staff1`, not
   `staff1-codex-desktop`). A host move is a registry edit plus re-init; the folder is
   never renamed (renaming breaks git worktree metadata and channel configs). The
   current host is recorded in the registry and in the folder's generated files.
   A suffix is added only when several instances share one role ID.
5. **Project-affecting decisions travel into the repository via PRs** (tracked docs:
   `docs/decisions/`, ADRs, issues). Role folders hold drafts only — anything that
   matters to the project must not die with the local machine.
6. **`pnpm install` runs inside worktrees only** (the pnpm store is shared); never in
   the `synloq-agents/` root.
7. **Prerequisite:** long paths enabled (`git config core.longpaths true` and the
   system-level Windows setting) — nested worktrees with `node_modules` exceed 260
   characters easily.
8. **dist divergence is normal:** a role's channel runs the dist of the main checkout
   from its generated config. Code a role changes in its worktree does not affect its
   own channel until merge + rebuild of the main checkout.
9. **One branch — one checkout.** Git enforces this across worktrees; treat it as a
   feature (no two roles edit the same branch).
10. **Folder/manifest sync is a manual operator duty.** `add-role` / `remove-role`
    create or retire the manifest entry; creating or archiving the role folder under
    `roles/` is done by hand. Drift detection (registry vs manifest) is a future
    `doctor` check — tracked as a separate issue, not a blocker.

## Role folders and hosts

A role folder is created on demand, not for uniformity:

- Folder-bound hosts (Codex Desktop, Claude Desktop) get the folder as the GUI
  project: the host config (`.codex/config.toml` or `.mcp.json`) sits at the folder
  root, so the GUI project and the working code coincide and no sandbox
  `writable_roots` tuning is needed.
- Kimi Work / OpenCode roles get a folder only when they need persistent notes.

The channel config has exactly one source: the Synloq home, generated by `synloq init`.
For a folder-bound role the generated config is copied from
`<synloqHome>/runtime/<key>/roles/<role>/` into the role folder once; the generated
files contain no self-references, so the copy is safe. If `doctor`/`reconcile` ever
break on a relocated role folder, that is a product issue ("arbitrary placement path",
linked to the per-host capability work) — not a convention problem.

## Stands

Acceptance and verification stands live under `_stands/` with their own Synloq home
and relay port. Stands are ephemeral: record a TTL, clean up after the verdict.
Existing pre-convention stands are legacy — they are not moved (their configs embed
absolute paths; moving would mint new project keys) and are deleted on TTL.

## Mitigations for the in-repo root (this stand)

- `synloq-agents/` is listed in `.gitignore` and `.prettierignore`.
- Recommended: exclude the folder from the editor's search/indexing.
- Verified on the first created worktree: a git worktree inside a gitignored folder
  does not disturb `git status` of the main checkout.

## Registry

`docs/conventions/agent-registry.yaml` (tracked) records the current placement:
role ID → host, folder, channel name. The team roster itself is owned exclusively by
`synloq.yaml`; the registry never duplicates role titles or instructions.
